# Optional Rust memory acceleration

The Rust library hashes lexical features used by project memory. Python retains
the API, tokenization rules, normalization, persistence, redaction and permission
checks. Streaming tokenization avoids holding a document-sized token list.
The native call processes at most 256 tokens per batch, uses a fixed 256-double
stack buffer, performs no I/O and retains no state between calls. It does not
accelerate model inference.

Build with the pinned Rust toolchain and checked-in crate lockfile:

```bash
cargo +1.99.1 build --locked --release --manifest-path native/Cargo.toml
cargo +1.99.1 test --locked --manifest-path native/Cargo.toml
export LOCAL_CODER_NATIVE_LIBRARY="$PWD/native/target/release/liblocal_coder_native.so"
PYTHONPATH=src python -m pytest -q tests/test_native_memory.py tests/test_context_memory.py
PYTHONPATH=src python benchmarks/benchmark_memory_vector.py
```

The path must be absolute. Linux uses `.so`; macOS uses `.dylib` and Windows
uses `.dll`. Only Linux x86-64 was validated during onboarding. Loading a library
executes native code: select only a trusted build, never a path from model output
or retrieved data. No library is downloaded or discovered automatically. An unset,
missing or incompatible library uses the streaming Python implementation. Native
input is ASCII tokens generated by the existing tokenizer; noncanonical inputs
and oversized native batches fall back to Python. The ABI version is checked,
but a version number cannot establish the safety of an arbitrary binary.

Persisted vectors keep the `lexical-hash-v1` label: raw counts and normalized
vectors match Python exactly, so existing databases need no migration. Tests
cover seeded inputs, batch boundaries, concurrent calls, invalid input, fallback,
empty vectors and persisted retrieval.

## Measured local result

On this Linux cloud machine, Python 3.12.14 and Rust 1.99.1, release build,
67,630 bytes of agent source, ten timed runs after warmup:

| Mode | Median vector time | Python allocation peak | Process peak RSS |
| --- | ---: | ---: | ---: |
| Eager Python reference | 67.70 ms | 404,315 bytes | 14,848 KiB |
| Streaming Python fallback | 55.03 ms | 14,223 bytes | 14,208 KiB |
| Streaming Rust hashing | 24.91 ms | 42,882 bytes | 14,464 KiB |

The accelerated path was about 2.7 times faster than the eager reference with
about 89% less Python-tracked peak allocation. Streaming Python used the least
Python allocation. Process memory changed only slightly. `tracemalloc` excludes
native memory; RSS includes process overhead and is noisy. These measurements
describe vector construction on this input, not overall agent latency. The
benchmark asserts exact vector parity and runs each mode in a separate process.
