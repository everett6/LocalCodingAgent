# Clin 50-point reliability and autonomy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox tracking.

**Goal:** Implement all fifty requested improvements with concrete runtime behavior, regression checks and truthful release evidence.

**Architecture:** Keep host-enforced scope, budgets, durable journals and evidence separate from model claims. Extend existing services with small modules and bounded schemas. Production integration and release readiness consume observed evidence; unavailable external validation remains explicitly unverified.

**Tech Stack:** Python/Pydantic/SQLite/asyncio, React/TypeScript, Electron/Code OSS, Node tests/Pytest, GitHub Actions.

**Spec:** docs/roadmap/clin-50-spec.json (the user's fifty requested acceptance outcomes).

## Global Constraints

- Security analysis and execution target this local repository only; no third-party probing, evasion, persistence, credential harvesting or resource-exhaustion activity.
- Do not weaken approvals, sandbox helpers, credentials, quota controls or conservative request admission.
- Preserve unfinished primary-checkout edits and protected environment files. Work only in this managed worktree.
- No paid inference, new service credentials or model downloads. Native signing/trademark/legal evidence cannot be fabricated.
- New telemetry is bounded, project-isolated, secret-filtered and distinguishes unknown data.
- Test changes with regression-first red/green checks where meaningful, then the final aggregate suites. No duplicate broad suites per worker.
- A checklist record or documentation alone does not count as implemented runtime behavior.

## Review Focus

- Unknown side effects after cancellation/crash: journals prevent automatic mutation replay.
- Alias/ancestor paths and unconstrained commands: scopes cannot become a prompt-only promise.
- Stale evidence and suppressed findings: changes cannot restore an incorrect verified/candidate state.
- Large output, histories and catalogs: bounds apply before memory expansion and avoid stale cache reuse.
- Unavailable external evidence: readiness and benchmark reports remain unverified and block the relevant release gate.
